<p>写这篇的起因，是看到不少「评测」把住宅 IP 说成一件很玄的东西，仿佛换了线路就万事大吉，还配上某个百分比当结论。我自己从机房出口换到原生家宽双 ISP 之后，验证确实少了，但过程里踩的坑同样不少，有几处认知是错的。这篇按纠偏的路子写，把流传最广的几个说法逐条摆出来，说清它们错在哪、正确的理解是什么，最后给出我自己评一条线时实际做的四个动作。</p>

<h2>一、评测里最容易传错的几个说法</h2>
<p>这几个说法有个共同点：都对了一半，所以传播得特别快。比如「住宅 IP 更稳」，在多数场景下成立，但把它当成「不会再碰验证」就错了。再比如「纯净度越高越好」，听起来没问题，可是各家算法不同，数字之间根本没法比。判断这些说法，最实用的办法是问一句：这个结论是在什么条件下得出的，样本多大，持续多久。</p>

<h2>二、误区一：换成住宅出口就不会再碰验证</h2>
<h3>验证是常态，不是异常</h3>
<p>任何出口都会遇到验证，区别只在频次。机房出口往往一登录就要求验证，住宅出口可能两三周才碰一次。我换线后的第十四天仍然遇到过一次滑块，那次是因为同一台设备上切换了两个号。所以正确的预期是「频次降低」，不是「归零」。</p>
<h3>频次降到什么程度算正常</h3>
<p>按我自己的记录，单个号一个月碰上零到两次，属于可以接受的范围；一周三次以上，就要考虑是不是环境还有别的问题。把频次记下来，比凭感觉判断可靠得多，建议至少连续记四周。</p>

<h2>三、误区二：纯净度百分比可以横向比</h2>
<p>这个百分比没有统一算法。有的按地址是否被公开列为代理来算，有的按历史滥用记录算，有的干脆按黑名单命中数折算。同一段地址在不同服务商那儿，可能一个写 95%，一个写 70%。拿两个数字做减法，得不到任何有效结论。</p>

<h2>四、误区三：换上家宽，环境就自动干净了</h2>
<h3>出口只是其中一层</h3>
<p>出口换了，还有时区、语言、浏览器指纹、解析记录这几层。我见过出口在温哥华、系统时区设在另一个城市、语言头又是第三种配置的组合，这种不一致比机房 IP 更容易引起注意。换线之后第一件事应该是把这几个字段对齐到出口所在地区。</p>
<h3>DNS 也要跟着走</h3>
<p>不少配置只给 HTTP 层挂了代理，DNS 还走本地解析，结果解析出的节点和出口地区对不上。检查方法很简单，在代理环境下跑一次解析，看返回的解析服务器在哪。这一项十分钟能改完，却经常被漏掉。</p>
<h3>双 ISP 不等于双线路</h3>
<p>「双 ISP」说的是这条地址的归属信息里能看到两家运营商，属于资料完整度的描述，不代表它有两条物理线路互为备份。真要冗余，还是得买两条独立线路，别把宣传词当功能。</p>

<h2>五、我自己评一条线时实际做的四个动作</h2>
<p>第一，查归属。用两个不同查询源比对城市和 ISP，两个源一致才往下走。第二，看路由。traceroute 到目标站点，记录前三跳和末跳，和已知的机房段比一比，末跳落在住宅网段才算过。第三，测连续可用性。挂一个小脚本每十分钟发一次请求，跑满二十四小时，统计失败次数和延迟波动。第四，算账。按自己的实际流量，分别算按量与月租的月度支出，选低的那个，别为面子选套餐。</p>
<p>这四步加起来不到两天，能挡掉大部分货不对板。价格方面，原生家宽月租常见在几十到两百元一条，按量常见每 GB 几元到十几元，具体看服务商当期报价，仅供参考。别指望找到一个数字直接比出高低，能被自己复现的指标才有意义。</p>

<h2>常见问答</h2>
<h3>换了住宅 IP 之后验证变多，是不是买错了？</h3>
<p>答：先看时间点。换线初期因为登录环境突变，短期验证增多是常见的，跑一周再统计。如果持续两周还在增加，再怀疑线路。另外确认时区、语言有没有跟着改，这几项没对齐，换什么线都白搭。</p>
<h3>评测里的延迟数据能直接参考吗？</h3>
<p>答：只能当量级参考。延迟和你所在位置、目标站点、当地网络都有关系，别人的 180 毫秒到你这里可能是 260 毫秒。自己测才有意义，测法要统一：同一目标、同一时段、各测二十次取中位数。</p>
<h3>按月租还是按量，怎么定？</h3>
<p>答：先按量跑满一个月。拿到真实流量再算，一般月流量超过五十 GB 时包月更划算，低于十 GB 按量更省。中间区间看你对账单可预测性的要求，能接受浮动就继续按量。</p>
<h3>同一条线能不能既给自己用又给同事用？</h3>
<p>答：技术上可以，但会把两个账号的环境绑在一起。如果两人的操作强度接近、都在正常范围内，风险可控；一旦其中一个人跑重活，另一个人也会受影响。建议按人分线，这是最省心的做法。</p>
